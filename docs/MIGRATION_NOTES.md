# 迁移说明

## 背景

这个项目不是简单把原有实现换成另一套 UI，而是把景观设计前期工作流重新组织为一个更适合前端展示、作品集输出和后续扩展的 Vue 3 工程。

迁移目标主要有两类：

- 保留原有业务链路中的关键价值
- 让前端项目可以独立运行和独立演示

## 保留的能力

当前版本保留了以下核心能力：

- 规范知识库导入
- 场地分析
- 设计任务书生成
- 参考案例推荐
- 在线案例目录检索与导入
- 历史记录与资产沉淀

这些能力已经不再依赖原型式页面组织，而是收敛为统一的前端工作流。

## 重构的部分

以下部分进行了明显重构：

- 页面结构：改为多路由、多页面工作台
- 状态管理：由集中式 Pinia 仓库统一承载
- 规则能力：迁移到前端服务层
- 案例推荐逻辑：迁移到 TypeScript
- 结果沉淀方式：加入历史记录和本地资产管理
- 运行模式：加入演示模式与远程模式切换

## 从原型流程到前端工程的变化

### 以前更像原型

- 更依赖单页面串联
- 更强调快速验证链路
- 后端能力承担更多逻辑

### 现在更像应用

- 页面职责明确
- 服务层边界清晰
- 全局状态可追踪
- 文档与项目结构更适合作品集展示

## 已迁移到前端的逻辑

- 知识库文本预检
- 文件分块与去重
- 轻量检索
- 场地分析与任务书的演示模式生成
- 规则修正逻辑
- 本地案例推荐逻辑
- 工作区快照持久化

## 没有做 1:1 迁移的部分

当前版本没有追求完全等价迁移，主要原因是本项目优先级是“前端独立可运行”。

未做 1:1 迁移的典型部分包括：

- 后端向量数据库能力
- 服务端会话状态
- 更复杂的工作流编排基础设施
- 专门的文件上传与导出后端服务

## 这样取舍的原因

- 降低环境依赖，方便本地启动和演示
- 让项目更适合前端岗位或作品集场景
- 保证在没有改动原后端仓库的前提下也能完整运行
- 给后续迭代保留更清晰的接口边界

## 当前版本新增的价值

- 首页总览和图表化展示
- 可配置的运行模式和提示词模板
- 本地工作区状态恢复
- 历史记录与资产中心
- 更完整的工程结构与说明文档

## 后续建议

- 如果要走真实生产链路，优先增加后端代理层
- 如果要提升知识库质量，可以引入嵌入式检索和更强的分块策略
- 如果要提升协作能力，可以增加云端存储、共享项目和权限管理
