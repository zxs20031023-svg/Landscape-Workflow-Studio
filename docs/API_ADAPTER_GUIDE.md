# 远程模型接入说明

## 当前接入方式

项目在远程模式下通过浏览器直接请求 OpenAI Compatible 接口：

```text
{Base URL}/chat/completions
```

请求逻辑位于 `src/services/llmService.ts`。

## 设置项

在设置页中可以配置以下参数：

- `API Key`
- `Base URL`
- `Model`
- `Embedding Model`
- `retrievalTopK`
- 任务书与场地分析提示词模板

其中当前实际参与远程对话请求的是：

- `API Key`
- `Base URL`
- `Model`
- 提示词模板

`Embedding Model` 目前更多是为后续扩展预留。

## 请求特征

当前实现的主要特征：

- 使用 `POST`
- 请求头携带 `Authorization: Bearer <API Key>`
- 请求体使用 `messages`
- 指定 `response_format: { type: "json_object" }`
- 期望服务端返回可直接解析的 JSON 内容

## 需要服务端满足的条件

如果要成功使用远程模式，目标服务通常需要满足：

- 允许浏览器跨域访问
- 支持 `chat/completions`
- 支持 Bearer Token 鉴权
- 最好支持结构化 JSON 返回

## 回退策略

为了保证页面始终可演示，当前实现做了自动回退：

- 如果运行模式不是 `remote`，直接走演示模式
- 如果没有填写 `API Key`，直接走演示模式
- 如果远程请求失败，自动回退到本地演示结果

这意味着即使远程服务不可用，页面流程仍然能跑通。

## 常见问题

### 1. CORS 报错

表现：

- 浏览器控制台提示跨域失败

原因：

- 目标服务未开放浏览器访问

建议：

- 先切回演示模式
- 或增加受控后端代理层

### 2. 返回内容无法解析

表现：

- 接口返回成功，但前端解析 JSON 失败

原因：

- 模型没有按 JSON 结构输出
- 服务端兼容性与当前请求格式不完全一致

建议：

- 收紧提示词模板
- 检查服务端是否支持 `response_format`
- 必要时由后端做结构化兜底

### 3. 浏览器可访问，但结果不稳定

原因通常包括：

- 模型温度或提示词不稳定
- 服务端对 JSON 输出支持较弱
- 需求文本过短，约束不足

建议：

- 补充更具体的场地描述与任务要求
- 优化设置页中的系统提示词和用户提示词模板

## 更适合生产环境的方案

如果后续要把远程模式做得更稳，建议按这个方向演进：

1. 浏览器仅请求自建后端代理
2. 后端统一封装模型供应商差异
3. 后端负责重试、结构化校验、日志和鉴权
4. 前端只消费稳定的业务接口

这样可以显著降低跨域、泄露密钥和返回格式不稳定的问题。
